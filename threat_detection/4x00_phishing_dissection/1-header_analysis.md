# Header Analysis

## Email 2 — meddefense-portal.com

### Header Evidence

- **From:** `noreply@meddefense-portal.com`
- **Return-Path:** `noreply@meddefense-portal.com`
- **Sending IP:** `91.234.99.107`
- **X-Mailer:** `PHPMailer 6.6.0`
- **Message-ID:** `<PHP-5D7E2F4A@meddefense-portal.com>`

### Received Chain Summary

1. The email entered MedDefense through `inbound-relay.meddefense.com`.
2. MedDefense's mail server `mx01.meddefense.com` received it from `mail.meddefense-portal.com` at `91.234.99.107`.
3. The sending server generated the message using `PHPMailer 6.6.0`.

### Anomalies

- **[HIGH]** SPF failed because `91.234.99.107` was not authorized to send mail for `meddefense-portal.com`.
- **[HIGH]** DMARC failed for `meddefense-portal.com`.
- **[HIGH]** DKIM was not present.
- **[HIGH]** The sender uses the lookalike domain `meddefense-portal.com` instead of the legitimate `meddefense.com` domain.
- **[MEDIUM]** The message was generated using `PHPMailer 6.6.0`, consistent with a web-based mail-sending application rather than the normal internal MedDefense mail infrastructure.
- **[MEDIUM]** The Message-ID is generated by PHP/PHPMailer and uses the same suspicious domain.

### Conclusion

The header chain shows that E2 came from external IP `91.234.99.107` through `mail.meddefense-portal.com`. SPF and DMARC both failed and there was no DKIM signature. The use of the lookalike `meddefense-portal.com` domain and PHPMailer-generated message strongly supports the suspicious classification.

The header analysis shows that E2, E3, E5 and E7 were all received from external mail servers rather than the MedDefense internal Exchange infrastructure.

The combination of external sending infrastructure, suspicious domains, authentication results and header anomalies supports the original suspicious classification from the initial triage.
